About p5.penplotter

I wanted to try plotting a drawing from a p5 sketch, while keeping the sketch familiar to work with. Recording the shapes as they are drawn seemed a useful place to start.

Why

I wanted to use my plotter from a p5 sketch. Supported plot.line(), plot.circle() and other shape calls draw on the canvas and record geometry in millimetres. plot.go() plans that recording when you start the plot. Clear at the start of a frame to replace earlier geometry, or leave it to accumulate.

Drawing in p5, planning in the engine

createPlot() creates an object that draws supported shapes and records them for the pen. createPlotterEngine() exposes the core directly, and drawRoute() draws its planned routes in p5. The adapter maps pixels to millimetres; geometry, cleanup, planning, exports and machine control stay in vanilla.penplotter.

When you supply a driver, the adapter checks the engine’s version and refuses one below its required minimum. A test checks that both READMEs give the same requirements; it does not test every possible version combination.

SVG capture and direct plotting

p5.plotSvg by Golan Levin records a p5 sketch as SVG and covers a wider drawing API. This adapter records a smaller set of explicit shape calls and can pass them to the EBB driver. SVG import and export are also available through the core; imported files must fit its supported subset.

The machine

Physical tests use my iDraw HSE / A2 with EBB firmware 3.0.2. Park the carriage at the physical origin used by the driver. You can write plot.go() at the end of draw(); it waits for a click to open the connection and start plotting. Other machines have not been physically tested here.

How this was made

AI helped me work on the connection between p5.js and the plotting engine. I wanted to keep room for the pleasure of working on the sketch myself.

The adapter was written with AI assistance, under my direction. I am responsible for what is here. See Setup to use the library in your p5 sketch.
